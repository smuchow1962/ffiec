# Reviewer feedback directory

> **What this directory is.** All reviewer feedback on the chain-of-custody corpus, organized by round. Spawned-reviewer rounds (9-16) live in numbered subdirectories. Outside-reviewer drops live in `outside/` or as `outside-*.md` files within a numbered round.
>
> **Two automation tools** (`tools/feedback-scrape.py` and `tools/feedback-watcher.py`) walk this directory, parse every reviewer-shaped markdown file, and produce a consolidated view at `SCRAPE-REPORT.md` plus a machine-readable summary at `scrape.json`.

## Drop conventions for outside reviewers

**Canonical location: `docs/feedback/outside/`.** Outside reviewers (FFIEC working group members, Big Four advisors, external security researchers, regulator IT staff, vendor-conformance reviewers) drop their feedback files here. Reviewers have been informed of this convention; future drops are expected at this location.

```
docs/feedback/outside/<reviewer-id>-<role-slug>.md
```

Examples:

```
docs/feedback/outside/jdoe-occ-cyber-specialist.md
docs/feedback/outside/herald-vendor-conformance-review.md
docs/feedback/outside/07-outside-reviewer-ai-platform-engineer.md
```

The scraper picks up everything under `outside/` and surfaces it in the dedicated "Outside-reviewer drops" section at the top of `SCRAPE-REPORT.md`.

### Round-scoped drops (rare)

If an outside reviewer wants their drop tied explicitly to a numbered round (for example, to comment on a specific round's close-out state), they may place the file at:

```
docs/feedback/round-N/outside-<reviewer-id>-<role-slug>.md
```

The `outside-` filename prefix marks it as an outside drop within a round directory. This pattern is supported but not the default — prefer `docs/feedback/outside/`.

## File-shape conventions

The scraper extracts findings most cleanly when reviewer files follow this shape:

```
# <Title>

> **Persona.** <Name>, <Role>. <Background sentence>.
>
> **Reading angle.** <One-sentence lens>.

## Questions

**Q1. <Question text>.**

**Status:** Answered | Partial | Gap

<Assessment paragraph; cite specific spec sections when applicable.>

**Q2. ...**

(more questions)

---

## Per-role roll-up

| Status | Count |
|---|---|
| Answered | N |
| Partial | N |
| Gap | N |
```

The scraper recognizes:

- `**Persona.** <Name>` heading or `**Reviewer.** <Name>` block to extract the reviewer's name
- `**Status:** Answered|Partial|Gap` lines (case-insensitive) to count per-question dispositions
- Roll-up table rows `| Answered | N |` etc. — when present, these override per-question counts
- The first non-heading paragraph as the file's headline summary

Files that do not follow the shape are still counted, but with `(unknown)` persona and best-effort status counts. Outside reviewers are encouraged to follow the shape; the scraper produces more useful aggregation when files are structured.

## Stopping criterion

The convergence target across rounds 9-16 is **0 gaps and 0 partials per role document**. Round 15 achieved this across all six spawned-reviewer roles with fresh personas. Outside drops are evaluated against the same criterion: an outside drop with `Gap > 0` or `Partial > 0` is a finding the corpus has not yet absorbed; a drop with `Answered` only is a confirmation.

## Tools

### `tools/feedback-scrape.py`

Walks the entire feedback tree and produces:

- `docs/feedback/SCRAPE-REPORT.md` — consolidated markdown report with per-round summary, per-file detail, trajectory across rounds, and a dedicated "Outside-reviewer drops" section at the top.
- `docs/feedback/scrape.json` — machine-readable JSON for tooling integration.

Run:

```
python tools/feedback-scrape.py
```

Flags:

- `--include-historical` — include the `historical-round-8-pre-hmac-rework/` archive (excluded by default).
- `--root <path>` — point at a different repo root.
- `--quiet` — suppress per-file console output.

### `tools/feedback-watcher.py`

Polls the feedback directory and emits a log line per detected file event (added / removed / modified). Optional `--on-change scrape` re-runs the scraper after every change.

Run:

```
python tools/feedback-watcher.py
python tools/feedback-watcher.py --interval 10 --on-change scrape
python tools/feedback-watcher.py --once    # single scan and exit
```

State and log files (hidden, auto-created):

- `docs/feedback/.watcher-state.json` — last-seen files and mtimes.
- `docs/feedback/.watcher-log.ndjson` — one JSON event per detected change.

Stdlib-only. No `pip install` required. Cross-platform.

### Recommended workflow

1. Outside reviewer drops their file into `docs/feedback/outside/` or `docs/feedback/round-N/outside-*.md`.
2. The watcher (running in a terminal) detects the drop and re-runs the scraper.
3. The scraper writes the updated `SCRAPE-REPORT.md` with the new drop surfaced at the top.
4. The convergence team reviews the new finding against the current corpus state and either closes the item (treating it as a partial/gap) or marks it Answered.

Without the watcher running, run the scraper manually after any drop:

```
python tools/feedback-scrape.py
```

## Stopping criterion + outside-drop integration

The corpus is considered converged when:

1. The most recent spawned-reviewer round produced 0 gaps + 0 partials across all six role documents (round 15 achieved this).
2. No outside drops remain open with Gap > 0 or Partial > 0 against the current corpus state.

Outside drops are integrated into the convergence cycle: each new drop is treated as either a closure-required finding (close it, then validate with another round) or a confirmation (no action needed). The scraper makes the open-outside-drop set visible at the top of `SCRAPE-REPORT.md`.
